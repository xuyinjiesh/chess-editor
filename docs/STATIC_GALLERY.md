# 无后端作品广场

作品广场与编辑器共用一个项目，访问 `#/gallery` 打开。作品和清单放在 `public/gallery/`，构建时复制到网站中；浏览、试玩、下载和分享都由浏览器完成。

适合由你独自发布作品：发布权限来自 Git 仓库的写入权限。访客可以下载、试玩和改编，页面上的「准备发布」只导出文件，不会写入网站。没有账号、数据库或投稿接口。

## 发布你的第一款作品

1. 在编辑器设计棋盘、初始布局和规则。分别测试双人操作与人机对弈。
2. 点击项目栏「发布」，填写作品标识、版本、作者、介绍、标签与玩法说明，点击「导出发布包」。广场页「准备发布」也会为当前编辑器草稿导出发布包。
3. 在本地项目根目录运行以下命令，参数可填写下载文件的完整路径：

   ```sh
   npm run gallery:add -- "my-game-v1.qijing-release.json"
   npm test
   npm run build
   npm run preview
   ```

4. 在预览页进入作品广场，检查介绍、封面、玩法和 AI。确认后提交生成的 `public/gallery/` 文件并推送到 `main`。仓库 Pages 工作流完成后，作品才会出现在公开网站。

发布脚本需要 Node.js 22.6 或更新版本，建议使用 Node.js 22 的较新版本或 Node.js 24。它直接复用前端的 TypeScript 格式校验和封面生成代码。

发布包扩展名为 `.qijing-release.json`，包含完整棋类设计、展示资料与自动生成的 SVG 封面。普通「导出」的 `.qijing.json` 只包含设计，用于备份和导入编辑器。发布脚本会重新生成封面，并且不会执行作品里的规则代码。

## 更新与分享

同一作品更新时保留「作品标识」，将版本由 `1` 增加为 `2`，再导出和导入。标识支持小写英文字母、数字与中间的短横线，例如 `forest-chess`。版本是正整数。

广场列表展示每个作品的最高版本；详情页可选择历史版本。分享按钮生成固定版本链接，例如：

```text
https://你的站点/chess-studio/#/gallery/forest-chess/v1
```

旧版文件会保留，导入命令拒绝覆盖已有版本。要修复已发布版本，请增加版本号。访问没有版本后缀的 `#/gallery/forest-chess` 会打开清单中的最新版本。

发布版本号与项目 JSON 的 `version: 1` 无关；后者表示文件格式。

## 文件布局

```text
public/gallery/
  index.json                     # 所有版本的展示资料与玩法说明
  forest-chess/
    v1/
      project.json               # 棋盘、棋子、区域、规则、界面
      cover.svg                  # 自动生成的静态封面
    v2/
      project.json
      cover.svg
```

`npm run gallery:check` 会验证清单、每个设计文件、标题与封面的一致性。`npm run build` 会先执行此检查，避免缺失或损坏的作品进入部署。

清单最多包含 1,000 个发布版本，文件上限为 8 MB；单个设计 JSON 不超过 500 KB。标签最多 6 个，玩法说明最多 6,000 字。

当前展示「六贯棋 · Hex」「异变象棋」「足球棋」「角斗棋」「迷你永恒棋」「震棋」「形意棋 · Onitama」与「石头剪刀布棋 · Intransitive」，已替换原有三款示例。将 `entries` 设为 `[]` 可以保留一个空广场。

足球棋和角斗棋由本站作者 xuyinjie 原创，资料在 `scripts/original-games.mjs`，根据作者的 `chess-room` 实现移植。足球棋使用 15 × 23 球场，支持角色差异化移动、持球、邻格抢球、传射、蓄力折线球和日字连跳。作者确认带球入门同样获胜；球员可走到底线两侧格，足球不能直接踢入这些格。角斗棋使用 3 × 3 空盘，每方十六枚储备、最多同时上场三子；作者确认禁中心只限全局第一手，将可留在储备，将、兵和士可按专属走法吃子。完整玩法见各作品详情。

两款原创作品使用通用规则界面，状态随走子保存在 `data`，支持悔棋、重做、人机对弈与复制改编。足球棋使用 `choices` 操作选项和 `markers` 棋子标记；角斗棋使用 `zones` 棋子储备区，在棋盘上下展示与场上相同的圆棋及剩余数量，点击后可上场，满三子或数量为零时禁用。足球场标线由 `football-pitch` 区域标签启用，保存在项目中；标线不会对其他作品生效。

迷你永恒棋支持双方在六个指定起始格内交换车、马、炮后确认布阵；红方先走。吃有色棋子后由行动方将其放回所属半场，放回后才换手；吃河中石则永久移除。守护者保护与每方一名的限制适用于移动和放回。电脑采用预设布阵，其后使用本地搜索。

震棋使用 8 × 8 方格棋盘，棋子落在格子中央，黑先白后，八方向同时击退，受阻不动、出界移除。按参考实现先判断落子是否连四，否则击退后检查双方；双方同时连四为和棋。

形意棋采用基础版 5 × 5 棋盘，每方一位师父、四位弟子。进入试玩后抽取五张招式，待换卡的印记决定先手；走子后将所用卡与待换卡交换。双方手牌和待换卡使用通用 `zones` 接口，分别放在棋盘上下及公共区；其他作品也可用此接口展示普通卡牌、带数量的备用棋子、牌堆和弃牌区，见 [规则界面协议](DEVELOPMENT.md)。招式图示与棋盘方向一致，编辑器翻转棋盘时也会翻转图示；无合法走法时停着换牌，擒师或师父进入敌方庙门获胜。招式选择不写入棋谱，卡牌状态随走子快照保存，支持悔棋与重做。随机性仅用于开局发牌，正式对局为确定性的完全信息搜索。

石头剪刀布棋（Intransitive / RPS2）由 webgoatguy 设计，依据视频所附 Meaf 试玩网站核对规则，资料在 `scripts/intransitive-game.mjs`。采用 9 × 9 固定阵型，双方各有 3 石、4 布、3 剪，蓝方先手。八向一步、相克吃子，攻入对角敌方基地、全歼或困毙获胜；沿用参考网站电脑对弈版连续 200 手未吃子和棋的规则。计数保存在 `data.quietPlies`，随悔棋和重做恢复。

- **六贯棋 · Hex**：11 × 11 菱形蜂巢棋盘，红连上下、蓝连左右，六方向连通胜负与路径标记；含第二手交换首子（换色并对调行列），支持本机双人、电脑、撤销重做与复制编辑。来源为中文维基百科和 Matthew Seymour 的 Hex 规则说明。

八款规则代码位于 `scripts/rules/`，完整代码随静态项目 JSON 下载和复制。`npm run gallery:featured` 可重新生成开发中的 v1 快照、目录资料及自绘 SVG 封面；此命令只用于维护这八个开发快照，公开版本的更新仍应增加版本号，使用常规发布流程。它保留无关作品与这八款作品的较新版本。

清单可选字段 `credits` 为来源与权利说明，`sources` 为最多六个 `{label,url}` HTTP(S) 链接。详情页分别显示数字实现、规则作者／视频介绍者和来源。迷你永恒棋原规则署名日出333；震棋仅核实到视频介绍者日出333，未推断其为规则发明者；形意棋署名 Shimpei Sato，链接 Arcane Wonders 的官方规则书。当前未取得公开授权证明，署名不能替代授权。作品名称、规则及资料的权利归属以原权利人声明为准。本项目自行生成封面，没有复用原站图片或视频素材。

下架时从清单移除对应版本；详情链接会显示「没有找到这个作品版本」。若也要撤下可直接访问的 JSON 和 SVG 文件，需要一并删除相应版本目录后重新部署。更新其他作品无需改动历史版本目录。

异变象棋包含作者设计的全部 50 种技能，公开幻子身份，支持三选一、瞬发目标、锦囊、持续效果和复杂连锁结算。技能说明、原版修正与测试方式见 [异变象棋迁移说明](INCIDENT_CHESS.md)。

## 草稿与试玩

- 广场浏览和试玩使用独立状态，不覆盖编辑器草稿。进入广场时，编辑器中进行中的电脑对弈会暂停。
- 试玩页右上角「全屏试玩」会按屏幕大小调整棋盘，支持双人试玩与人机对弈；点击「退出全屏」或按 Esc 返回，当前对局与棋谱保留。不支持浏览器全屏的设备使用铺满窗口的视图。
- 「复制到编辑器」创建新 ID 的副本，并先把原草稿保存在本地「我的作品」。这仍受现有本地作品库最多 20 项的限制，重要作品请导出备份。
- 详情页的「联机游玩」载入当前选定版本的副本，并直接打开联机房间窗口；同样会先保存原草稿。填写昵称并创建房间后，可分享房间码或邀请链接。
- 下载和发布包保存初始设计，不包含当前对局、棋谱、API Key 或联网设置。
- 人机对弈复用本地 AI 引擎，无需远程模型。自定义作品的适用范围及规则接口见 [本地 AI 说明](LOCAL_AI.md)。

## 部署与验证

广场使用 hash 路由，静态服务器无需配置路径重写。加载资源时遵循 Vite 的 `base`，可部署在根路径或 GitHub Pages 的仓库子路径。现有 Pages 工作流会自动指定仓库路径。

若要本地模拟 `/chess-studio/` 子路径：

```sh
npm run build -- --base=/chess-studio/
npm run preview -- --base=/chess-studio/ --port 4174
```

访问 `http://localhost:4174/chess-studio/#/gallery`。浏览器集成测试可对生产预览运行：

```sh
node scripts/test-gallery-browser.mjs
node scripts/test-hex-game-browser.mjs
node scripts/test-onitama-browser.mjs
node scripts/test-game-zones-browser.mjs
node scripts/test-original-games-browser.mjs
node scripts/test-intransitive-browser.mjs
```

默认测试地址是 `http://127.0.0.1:4173/`。使用子路径预览时设置 `GALLERY_TEST_URL`，例如 PowerShell：

```powershell
$env:GALLERY_TEST_URL='http://127.0.0.1:4174/chess-studio/'
node scripts/test-gallery-browser.mjs
node scripts/test-onitama-browser.mjs
node scripts/test-game-zones-browser.mjs
node scripts/test-original-games-browser.mjs
node scripts/test-intransitive-browser.mjs
```

测试使用 Playwright Chromium；未安装该浏览器时尝试系统 Microsoft Edge。截图和测试导出文件保存在 Git 忽略的 `artifacts/`。
