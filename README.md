# 棋局工坊 v2 · Chess Studio

一个可静态部署的中文通用棋类编辑器。React 19、TypeScript、Vite；国际象棋规则使用 chess.js，P2P 联机使用 PeerJS。棋盘与棋子使用本地 CSS、SVG 网格与系统字体符号，无图片服务依赖。应用版本为 2.0.0，npm 项目名为 `chess-editor-v2`。

## 运行

```sh
npm install
npm run dev
```

访问终端显示的地址（默认 `http://localhost:5173`）。

```sh
npm test         # 规则、项目格式与 AI 接口契约测试
npm run build   # 类型检查与生产构建
npm run preview # 预览 dist
```

`dist/` 可直接部署到任意静态站点服务。国际象棋、中国象棋、五子棋、黑白棋、井字棋、本地编辑与导入导出均不需要应用后端。Google Fonts 无法加载时自动使用系统字体。

## 已实现

- 棋盘：3–24 行列、方格 / 交叉网格 / 格内网格 / 中国象棋 / 六边形图块、预设和自定义配色、坐标、翻转、缩放。
- 棋子：两方阵营、自定义棋子类型与符号、国际象棋 / 中国象棋红黑圆棋 / 棋石 / 文字图章外观、点击或拖拽摆放、擦除。
- 区域：绘制多个带颜色和标签的区域；规则通过 `project.regions` 读取。
- 规则：国际象棋合法走子（含易位、吃过路兵、升变、将死、重复局面和棋）；中国象棋（马腿、象眼、炮架、九宫、河界、将帅照面、将军、将死及困毙判负）；自由五子棋；黑白棋自动翻转与跳过无合法落点回合；井字棋。
- 自定义 JavaScript：规则编辑器、沙箱示例运行、错误提示和 2 秒执行期限；可更改棋子、回合、胜负和 `state.data`。
- AI：直连兼容 Chat Completions 的接口，生成完整项目，校验、预览后手动应用；支持取消。没有内置或共享 API Key。
- UI：游戏名称、简介、强调色、走子提示和棋谱显示设置均可编辑和由 AI 生成。
- 保存：当前设计自动存入浏览器 localStorage；手动保存至本地作品库（最多 20 个）；完整项目 JSON 导入、导出；修改与对弈分别支持撤销 / 重做。
- 联机：P2P 房主托管、自定义 PeerServer 和 ICE/TURN，或自托管 WebSocket 中继；房间码 / 邀请链接、角色分配、最多 8 人含观战、房主校验、棋局和棋谱同步、断线反馈。
- 响应式桌面 / 手机布局、键盘焦点、快捷键、对话框焦点约束。

## 棋盘交互与快捷键

棋盘与棋子视觉直接移植自用户的 WSL `chess-editor` 仓库（`styles.css`、`src/ui/board.js`、`src/render.js` 和 `packs/ui-*.json`）：渐变厚边框、衬线国际象棋符号、奶油色红黑圆棋、高光棋石与落点反馈。棋盘属性提供经典木色、温润玉石、浅色大理石、水墨素纸、午夜、星云、素纸高对比、木色棋墩 8 套风格，也可自定义颜色。深色棋盘单独提高黑方棋子对比度，外围坐标跟随工作台主题。

JSON 项目格式仍使用 `version: 1`，与应用版本独立。新增可选 `board.theme` 字段；旧文件缺少此字段时保留原有配色，可正常导入，当前主题也随 JSON 导出保存。已有浏览器作品不会被新模板配色覆盖。

参考原 `chess-editor` 仓库的 `src/render.js`、`src/app.js` 和主题样式，合并到现有 React 工作台：棋子按稳定 ID 渲染，移动平滑滑行，落子弹入、吃子淡出、选中抬起、黑白棋翻面与升变反馈。拖拽使用 Pointer Events，同时支持鼠标和触屏；翻转后坐标、玩家位置和拖拽落点一起更新。系统开启「减少动态效果」时自动关闭动画。

棋盘根据可用空间和行列比例自适应。试玩自动收起模板侧栏和编辑标签；点击「放大棋盘」或按 `G` 进入专注模式，隐藏两侧面板，`Esc` 返回且保留棋局。右下角可调整 60%–140% 缩放，点击百分比还原。顶栏月亮 / 太阳按钮切换夜间与日间主题；首次跟随系统，手动选择保存在当前浏览器，不改变项目的棋盘配色或导出格式。

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl / ⌘ S` | 保存作品 |
| `Ctrl / ⌘ Shift S` / `Ctrl / ⌘ O` | 导出 / 导入 |
| `Ctrl / ⌘ Z` / `Ctrl / ⌘ Shift Z` / `Ctrl / ⌘ Y` | 撤销 / 重做 |
| `Space` | 编辑 / 试玩（焦点在普通按钮时仍激活该按钮） |
| `V` / `P` / `E` / `R` | 选择 / 放置 / 擦除 / 区域工具 |
| `1`–`9` / `Delete` | 选择棋子类型 / 删除选中棋子 |

输入框、下拉框、可编辑文字与 IME 输入期间暂停棋盘快捷键；输入框保留原生撤销，保存 / 导出快捷键仍可用。弹窗内由弹窗处理按键，避免影响背后的棋局。编辑工具只在编辑模式生效，联机仍遵守已有角色与撤销限制。

## 中国象棋与落点布局

中国象棋模板使用 9 列 × 10 行交叉点棋盘，带楚河汉界、九宫线和兵炮定位标记。红方先手，红黑棋子可分别显示帥 / 將、仕 / 士、相 / 象、兵 / 卒等文字。可在侧栏或模板库载入，直接试玩或开房间。

内置规则覆盖基本走法、自将检查、合法落点提示、将军、将死和困毙判负；暂不实现长将、长捉、重复局面与自然限着等竞赛裁定。内部 `white` 表示红方（从下向上走），`black` 表示黑方，以复用既有房间和自定义规则协议。

交叉网格 `grid` 的线条仅连接最外侧落点，不向边框延伸；`cells` 将线画在格子边界，供黑白棋、井字棋等格内落子游戏使用。象棋样式 `xiangqi` 固定为 9 × 10，修改尺寸后自动改用交叉网格与自定义规则。新字段兼容原 version 1 项目，旧文件可以正常导入；旧作品保留原先选择的棋盘布局。

## AI 接口

在「AI 助手 → 配置模型」填写：

1. API 基地址，例如服务商提供的 `https://host/v1`，也可填完整 `/chat/completions` 路径。
2. 模型 ID。
3. API Key（本地无鉴权服务可留空）。

浏览器会把当前项目和设计描述发送到你指定的模型地址。接口必须支持浏览器 CORS；HTTPS 页面不能调用普通 HTTP 的远程服务。Key 只留在当前页面的 React 内存中，刷新清除；只有 API 地址与模型名称会保存。服务商可能按其价格收费。

生成的是完整 `Project` JSON。规则函数可以由模型直接编写，不必套固定棋子走法；UI 目前为可配置工作台，不执行模型生成的任意 HTML。生成结果通过结构校验后展示预览，点击「应用这个设计」才更新项目。

## 自定义规则协议

`src/model.ts` 定义完整的 Project / GameState / Move 类型。坐标是从左上角开始的 0 基 `row` / `col`。六边形为图块外观，邻接关系由自定义代码定义，不会自动套用方格走法。

```js
function onMove(state, move, project) {
  // state: { pieces, turn, winner, history, data }
  // move: { from?: {row,col}, to: {row,col}, promotion?: 'q'|'r'|'b'|'n' }
  // project: board, pieceTypes, regions, rules, ui ...
  // 移动型规则先选棋子，落子型规则可没有 from。
  return {
    valid: true,
    pieces: state.pieces,       // 必需：移动完成后的完整棋子列表
    turn: 'black',             // 必需：下一回合 white 或 black
    winner: null,              // null / white / black / draw
    data: { energy: 3 },       // 可选：JSON 可序列化自定义状态
  };
}
```

拒绝走子返回 `{ valid: false, message: '原因' }`。棋子对象为 `{id,type,side,row,col}`，其中 `type` 对应 `pieceTypes[].id`。移动、翻面和升变时保留原棋子的 `id`，新建棋子才分配新 ID，让移动动画连续。规则可通过完整状态转换实现连跳、传送、额外回合、资源、特殊胜利条件等。当前阵营数量固定为白 / 黑两方。

每次执行会创建无同源权限的 sandbox iframe，在其中创建专用 Worker。CSP 禁止网络访问，Worker 无 DOM / localStorage 权限，主页面在期限结束后移除整个沙箱。返回的棋子、回合和状态经过结构校验。浏览器沙箱不为恶意代码提供独立进程内存配额，极端资源分配仍可能造成标签页资源耗尽；不要载入未知来源的代码。

国际象棋从编辑布局开始新对局；位于初始位置的王车视为具有易位权。导出文件保存**项目设计和初始布局**，不保存正在进行的对局；如需持久棋谱或重连恢复，可在当前协议上扩展。区域效果只由自定义规则决定，内置经典规则不解释区域标签。

## 联机部署

### 房主浏览器托管（P2P）

创建房间，将房间码或链接发给好友。默认 PeerJS 公共信令服务仅用于建立 WebRTC 连接，游戏状态通过数据通道传输；信令服务可用性取决于外部网络。双方使用相同的站点或相同协议版本即可。

「自定义信令 / TURN 服务」支持自建 PeerServer 的 HTTP(S) 地址与标准 `RTCIceServer[]` JSON。在严格 NAT、防火墙或企业网下可能需要 TURN，否则请使用 WebSocket 中继。自定义信令与 TURN 凭据不会写入邀请 URL，加入者需要自行配置。关闭房主页面会结束房间；不提供自动重连 / 房主迁移。

### 指定服务器（WebSocket 中继）

```sh
npm run server
# 默认监听 8787，使用 PORT 环境变量可覆盖
```

在联机窗口选择「指定服务器」，本机开发填 `ws://localhost:8787`。跨设备请填可访问的主机地址；正式 HTTPS 站点需要反向代理 TLS 后的 `wss://your-server`。静态站点托管不包含这个可选 Node 服务器，需要单独启动它。

中继进程只负责房间和消息转发，规则权威仍在房主浏览器。房主校验对方身份、回合、状态版本和合法走法，再广播新状态。房主执白，首位加入者执黑，其余观战。中继有消息体积、频率、房间人数和心跳限制；没有账户、持久化、断线恢复或竞技防作弊。持有码者可加入，适合朋友间私局。

如果使用带登录和访问控制的静态托管平台，还需要确保受邀者具有站点访问权限；房间码本身不会改变站点访问权限。
